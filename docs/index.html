Ranking Webpages for Next-Month Click Decline

February search and engagement signals are used to rank webpages that later have lower average daily clicks in March. The output is a human-reviewed queue, not an automatic refresh decision.

Hassan Raza
Abstract Data Methodology Results Validation Errors Recommendations Limits Reproducibility

Abstract

This capstone examines whether February search and engagement signals can help prioritize webpages that later experience lower average daily clicks in March. The analysis uses 23,703 webpages from 19 anonymized clients. Six February-only features were evaluated with a client-grouped holdout so that all four test clients were unseen during training.

A February CTR baseline was compared with logistic regression. Both methods reached 100% Precision@20 and 98% Precision@50. The CTR baseline had slightly higher average precision: 0.8755 compared with 0.8619. The ranked review queue therefore uses February CTR, with a warning for low-volume pages. These results are observational and specific to this dataset, this split, and the February-to-March 2026 window.

Data

The notebook reads page-level Google Search Console and Google Analytics 4 rows for February and March 2026 from the FlyRank internship warehouse through DuckDB. No raw warehouse export is in the public notebook. Each row is one anonymized webpage for one anonymized client.

Features come only from February: average daily impressions, average daily clicks, weighted average search position, average daily sessions, engagement rate, and click-through rate. March is used only to build the label. A page is labeled declined when its March average daily clicks are lower than its February average daily clicks.

Client names, domains, URLs, private queries, tokens, and raw warehouse files are not published. Client and content identifiers are kept for grouping only. They are not model features.

Methodology

CTR baseline

Pages are ranked by February click-through rate. A higher February CTR receives a higher baseline score. The same test pages and ranking metrics are used for both methods.

Logistic regression

Six February features are standardized, then a logistic regression model estimates a decline probability. The random seed is 42. Every page from a client stays in either train or test.

The reported metrics are the test-set base rate, Precision@20, Precision@50, and average precision. Accuracy is not the selection metric, because the goal is a short review queue.

Results

The test set has 1,671 pages from four clients that were not in training. The test decline rate was 23.22%.

Key finding

The two methods tied on the top 20 and the top 50. The CTR baseline was 0.0136 higher on average precision, so it is the ranking used for the review queue. Logistic regression stays useful for seeing how the other features move together. It does not replace the baseline on this holdout.

Validation and leakage

Training used 22,032 pages from 15 clients. Testing used 1,671 pages from four unseen clients. Client overlap was zero. All six features are from February. March data is only the label.

These columns are not features: client_hash_id, content_hash_id, decision_month, march_avg_daily_clicks, and declined_next_month.

February CTR had a standardized coefficient of 3.8752. Removing it dropped Precision@20 from 100% to 40%, Precision@50 from 98% to 36%, and average precision from 0.8619 to 0.4231. That is concentration on one February feature, not a March leak. No direct future-data, target, or identifier leakage was found.

Error analysis

At a 0.50 threshold the logistic regression model produced 1,252 true negatives, 172 true positives, 31 false positives, and 216 false negatives. It missed more declining pages than it falsely flagged, so the rank is more useful than the hard cutoff.

High-confidence false positive

Decline probability 0.9991, and the page did not decline. It had 5.50 average daily impressions, 0.32 average daily clicks, and a February CTR of 5.84%. A few clicks made CTR look high.

Borderline false negative

Decline probability 0.4985, and the page later declined. A small threshold change would have flipped the class. The 0.50 cutoff hides uncertainty.

High-visibility false negative

Decline probability 0.4194, and the page later declined. It had 232.18 average daily impressions, average position 7.16, and a February CTR of 0.09%. CTR does not explain every later drop.

Ranked recommendations

The queue sorts unseen test pages from highest to lowest February CTR. On this holdout, all 20 pages at the top later had lower average daily clicks in March. Most of those pages also had very low impression and click volume, so the reason code is: high CTR on low volume, verify stability.

For each high-priority page, a reviewer should:

  1. Check whether February volume was large enough for a stable CTR.
  2. Look at the March and recent trend.
  3. Check seasonality and changing search demand.
  4. Review position, impressions, and competing pages.
  5. Inspect freshness, relevance, and technical issues.
  6. Choose monitoring, an update, or no action.

The queue does not prove that high CTR causes decline, and it does not prove that refreshing a flagged page will help.

Limits

  • One window only: February features and a March outcome.
  • Four unseen test clients, and one grouped split.
  • The model’s useful signal is mostly February CTR.
  • CTR is unstable when impressions and clicks are small.
  • The label records only whether clicks were lower, not how large, how long, or why.
  • Nothing here should automatically update, remove, or rewrite a page.
